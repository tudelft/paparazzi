◆ ir_camera_close()

int ir_camera_close ( void )

Stop any active stream and release all vendor camera resources.

Returns
0 on success, or the stream-close SDK error code.

This is the final camera teardown path. Frame buffers are managed by the stream-off functions because worker threads must stop using them before release.

◆ ir_camera_open()

int ir_camera_open ( CameraParam_t * camera_param)

Initialize the UVC SDK, open the Tiny 1-C, and select the required stream mode.

Parameters
camera_paramReceives the selected device and endpoint configuration.
Returns
0 on success, an SDK error code on SDK failure, or -1 when the required camera or stream mode is unavailable.

Combined image-and-temperature output uses the vendor's second endpoint mode; image-only and temperature-only builds use the first. Preserving that index is essential because the combined endpoint has twice the visible image height.

int ir_camera_stream_on_with_callback ( StreamFrameInfo_t * stream_frame_info,
void * test_func )

Start callback-mode acquisition and invoke user code for each received frame.

Parameters
stream_frame_infoShared stream configuration passed back as callback context.
test_funcVendor-compatible callback function pointer.
Returns
SDK status from stream startup or Y16 preview startup.

Callback mode bypasses polling semaphores: the SDK owns callback timing, and the callback must finish quickly enough to avoid delaying frame delivery.

Note
Keep the sample process alive for 100 seconds so asynchronous callbacks continue to arrive; production code should use its own lifecycle mechanism.

◆ stream_function()

void * stream_function ( void * threadarg)

Poll raw frames, split their planes, and hand them to display and temperature workers.

Parameters
threadargPointer to the shared StreamFrameInfo_t instance.
Returns
Always NULL when the worker stops.

The done semaphores make the producer wait until both consumers have finished before overwriting shared buffers. Three consecutive acquisition failures trigger shutdown so blocked consumers are released instead of waiting forever.

Note
Gain switching and overexposure protection are optional SDK policies. Enable them here only after selecting thresholds suitable for the product's operating range.
