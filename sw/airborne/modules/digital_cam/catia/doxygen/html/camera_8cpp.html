FrameInfo_t * temp_info,
AutoGainSwitchInfo_t * auto_gain_switch_info )

Switch gain only after a sustained sequence of out-of-range frames.

Parameters
temp_frameCurrent raw temperature plane.
temp_infoDimensions and format of temp_frame.
auto_gain_switch_infoPersistent counters and post-switch settling state.

Consecutive-frame thresholds provide hysteresis so isolated hot or cold pixels do not make the camera oscillate between high and low gain. Detection is paused after a switch while the sensor settles into its new gain mode.

Note
Skip detection immediately after switching because unsettled sensor frames are not reliable evidence for another gain change.
Require repeated detections before switching to reject transient scenes.

Parameters

Detection runs every tenth frame to reduce processing cost. Protecting the detector takes priority over image continuity, so automatic shutter control remains disabled until the configured closed interval has elapsed.

Callback mode bypasses polling semaphores: the SDK owns callback timing, and the callback must finish quickly enough to avoid delaying frame delivery.

Note
Keep the sample process alive for 100 seconds so asynchronous callbacks continue to arrive; production code should use its own lifecycle mechanism.

◆ stream_function()

void * stream_function ( void * threadarg)

Poll raw frames, split their planes, and hand them to display and temperature workers.

Parameters
threadargPointer to the shared StreamFrameInfo_t instance.
Returns
Always NULL when the worker stops.

The done semaphores make the producer wait until both consumers have finished before overwriting shared buffers. Three consecutive acquisition failures trigger shutdown so blocked consumers are released instead of waiting forever.

Note
Gain switching and overexposure protection are optional SDK policies. Enable them here only after selecting thresholds suitable for the product's operating range.
