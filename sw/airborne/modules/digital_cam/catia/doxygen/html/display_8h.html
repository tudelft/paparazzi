◆ display_function()

void * display_function ( void * threadarg)

Consume published image frames and acknowledge each completed buffer use.

Parameters
threadargPointer to the shared StreamFrameInfo_t instance.
Returns
Always NULL after streaming stops.

Waiting on image_sem transfers read ownership from the producer. Posting image_done_sem after display prevents the producer from overwriting the shared image plane while conversion or output is still in progress.

◆ display_init()

void display_init ( StreamFrameInfo_t * stream_frame_info)

Allocate conversion scratch buffers and start the optional ffplay sink.

Parameters
stream_frame_infoStream geometry and frame-rate configuration.

Two RGB-sized buffers support conversion and orientation operations without modifying the producer-owned image plane. Missing ffplay is nonfatal because capture and temperature processing remain useful in headless deployments.

void display_one_frame ( StreamFrameInfo_t * stream_frame_info)

Process, orient, and present one image frame through enabled display backends.

Parameters
stream_frame_infoShared image plane and display configuration.

ffplay consumes the processed BGR24 frame from image_tmp_frame2. A broken pipe disables only video output so acquisition and temperature processing continue. The optional OpenCV path visualizes the original 16-bit image independently.
